# 字幕翻译与分段配音联合流程契约

本批推进 G19、G32、G33 和真实广告主链路，不替代 G01–G38 的原关闭条件。
本文件在本批模型实测前建立，质量结果和失败须另存原始证据。

## 输入与调用

`dub subtitles` 接受本地 UTF-8 SRT、中英源/目标语言、具名 Kokoro 音色，
以及可选的逐 cue 音色表、术语表、时窗策略和时间线放置参数。
中英双向使用已有 OPUS 包；简体/繁体中文保持显式选择。
模型依赖和运行环境必须已经在本机；不下载，不使用虚拟化。

SRT 按文件原顺序处理，记录原编号、原文本与毫秒时码；不静默跳过损坏块。
只接受无内嵌格式指令的普通字幕文本，格式化字幕仍是完整产品的开放范围。
输入上限 1 MiB、1–1000 cue，每段最多 3000 字符；模型 token 上限仍拒绝截断。
源字幕可重叠，但默认拒绝，只有显式 `--overlap-policy mix` 才允许混音。
应用时目标轨道必须显式存在、类型正确且未锁定/静音；不覆盖已有片段。

## 声音与时间

一次 voice worker 内加载一次 Kokoro，复用于同批所有 cue 和语速重试。
每段先按基础语速完整合成，保留该原始 WAV。
以实际单声道 24kHz、16-bit WAV 样本数检查是否容纳于原 cue 毫秒时窗。
工程 ticks_per_second 须能整除 1000；起点按整数毫秒换算，声音时长向上取整到工程 tick。
不使用截断、自动改写文本、atempo 或静默放宽时窗来满足检查。

- `reject`：任一段超长即拒绝提交整批；保存受管失败目录用于复核。
- `speed`：最多生成 3 次（原始加 2 次重试），语速不超过显式上限（最大 2）。
  下次语速为 `min(max_speed, current_speed * actual_samples / slot_samples * 1.03)`。
  到达上限仍放不进时拒绝整批。
- 初始语速范围 0.5–2；加速模式要求上限不低于初始语速。
- 单次生成最多 300 秒声音；空、非有限值、静音、错误格式或响应不一致拒绝。

控制器独立读取所有 WAV 的格式、实际帧数、PCM RMS 和哈希，重算语速序列和 fit。
每条最终声音形成独立可编辑音频资产和片段，从原 cue 起点开始，长度采用实际声音时长。
字幕保持原 cue 时间窗，可选择译文或双语；原文、译文和所有语速尝试均留存。
这是 cue 级安排，不是音素/字词对齐或口型同步，不据此关闭完整 G15/G19。

## 设备、预算和失败

翻译与配音分别选择 CPU/CUDA，`auto` 优先 GPU，`cuda` 严格失败。
两个任务可使用不同 CUDA 运行库；顺序运行，避免同时占用两套模型。
auto 仅在实际 CUDA worker 失败时允许已验证 CPU 包重试，CPU 使用新的工作子目录。
损坏模型包、取消、超时、字幕超长和语义/协议错误不得伪装为 GPU 故障回退。
总超时包括准备、包校验、翻译、配音、检查与提交前操作；运行中的原生子进程可取消。
记录设备、回退原因、模型初始化次数、推理时间、各段实际样本数、语速及文件哈希。

所有新媒体、模型许可与报告在持久化受管任务中暂存，只有全批通过才发布到派生资产。
一次外层项目事务提交所有资产、权利、音轨、字幕、快照和操作记录。
失败/取消/超时恢复原工程，不保留可误发布的半批工程。
超时窗的正常拒绝保留原始受管目录与失败报告；显式 recover 可预览及清理。
崩溃后依现有恢复机制区分已提交资产、未提交输出、活跃任务与已被修改文件。
已提交模型许可证据也必须被恢复引用保护。

## 权利、预检和验收

源 SRT 和生成文本/声音默认 unverified、internal，不把模型许可等同于内容发布授权。
复制模型原许可和来源，保持源文→翻译→配音的依赖链与摘要。
`--dry-run` 做解析、设备/模型包与轨道预检，不加载模型、不生成声音、不修改工程。
保留未知实际时长，不把预检当成 fit 成功。

本批须验证 GPU、CPU、超长拒绝、加速成功/上限失败、重叠显式混音、语音复用、
取消、超时、事务回滚、工程包往返、安装版和统一 Skill 的真实调用。
自然发音/韵律、翻译语义、多语种、说话人自动识别、字词精标与口型仍按原目标验收。
