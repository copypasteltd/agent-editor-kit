# 原生字形覆盖率、分块颜色与状态复用契约

本批延续既有文字功能和 G01–G38 全部原关闭条件，解决完整 Float32 原生图造成的资源及运行成本。既有 8bit 字形覆盖率不升级为浮点覆盖率；媒体及作者颜色全程保持在明确线性工作域。

1. 原生 FFmpeg 只输出独立组件的原始 `gray` 字节覆盖率。通过实际 256 码值探针验证无色彩变换、范围压缩或离散恢复误差。保留真实字体、塑形、度量、组件几何和样式拒绝行为。
2. 作者颜色使用原生解析器及明确 sRGB→工作域变换。底框、阴影、描边、填充按顺序执行分块 Float64 source-over，每组件边界返回 Float32；覆盖率与颜色 alpha 相乘一次。最终段落动画 alpha 只施加一次。零 alpha RGB 清零。
3. 逐词仍为两份完整段落的二值选择。选择蒙版使用已有原生度量及空间表达式，必须仅含 0/255，不把选中文字重复绘制。普通及活动颜色共享几何覆盖率；组件顺序和各自颜色独立。
4. 打字机使用原作者时钟的完整字素前缀，保留固定段落锚点和基线。缓存按实际前缀字节、字体、几何及原生图内容寻址，不按时钟取整，也不忽略动态位置。半开范围、父倒放左极限和裁切偏移保持。
5. 原生栅格逐张执行；字节覆盖率 LRU 和既有 Float32 表面 LRU 各自受明确字节上限约束，命中内容不可写。每次工作区准入包括四张 Float32 表面、原生字节栅格/暂存、两个缓存上限及分块空间，默认总估算不超过 768MiB。该估算不是原生/宿主进程峰值 RSS 硬上限。4K 四组件及选择组合须实际核验，较小显式预算仍前置拒绝。
6. 透明度/开关仅解释编译器产生的数值表达式，以白名单 AST 实现并保留惰性条件分支；不使用 Python eval 或执行任意作者代码。原生位置表达式继续由本机 FFmpeg 执行。所有循环、读取和原生生命周期保留取消响应。
7. 新模块加入实现 SHA、安装包和标准命令依赖读锁。冻结源码先进行文字专项核验，再对逐字节相同的安装版验证文字/浮点/默认路径回归；以独立原生 RGBA8 覆盖率和 Python Float64 公式核对 4K 组件，真实 Skill 验证预览、成片、恢复、队列及包迁移。
8. 性能比较使用相同输入、时钟和输出设置，明确工程缓存、操作系统页缓存及并行环境，保留上一安装版作为对照。输出颜色误差、字形状态、音频、尺寸、时长和全部时钟分别验证。不得把更小输入、单帧或缓存命中冒充完整成片加速。

CPU 执行；GPU 字层、复杂 Bidi、富字幕、自然视听、HDR、跨平台及完整目标继续开放。不得放宽原有像素、时钟或目标关闭条件。
