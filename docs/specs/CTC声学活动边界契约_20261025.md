# CTC 音频活动边界估计契约（2026-10-25）

目标是改善已有 CTC 字符峰过窄造成的词边界误差，不修改 G15 的原精度门槛、作者参考、音频或原稿。原六词和独立七词必须逐字节保留，最大起止误差仍为 2/30 秒（66.6667ms）。本契约在本方法取得候选结果及评分前写入；不得以移动参考、固定补时、删词或均分字符过关。

## 输入、方法和冻结参数

- 显式 `subtitle align --granularity whitespace --boundary-mode activity`；默认 `ctc` 保持原始字符峰语义。新模式不声称解决连续语音的内部词界、中文逐字、歌词或重叠语音。
- 使用真实 GPU/CPU Wav2Vec2 CTC 结果及同一请求实际解码的 16kHz、单声道 signed-16 PCM。模型和边界估计器不读取作者时间参考；独立评分在推理/估计之后读取。
- 原始字符帧/样本时钟不变，原始词区间另存 `raw_units`。从实际 PCM 以 80 样本（5ms）帧构建整数 RMS；分块处理，每块最多 2048 帧。DC 取均匀子采样（步长 max(1,N//64000)）的中位数，取整数。
- RMS 用去 DC 后平方和/实际帧长的整数平方根。噪声水平取第 floor((F−1)/5) 个有序 RMS，参考强度取第 floor(95(F−1)/100) 个。高阈值 max(4,4×noise,ceil(reference/100))，低阈值 max(2,2×noise,ceil(reference/316))；均为 PCM 整数，不使用作者阈值或参考时间。
- 低阈值活动连续块之间仅填 ≤8 帧（40ms）空洞。候选区间至少 4 帧（20ms），且含至少一帧高阈值活动。当 noise>0 且 reference≤4×noise 时保留原 CTC，记录低信噪比；不得根据参考答案调整阈值。
- 区间依据实际声音计算，不按原词区间统一加减。只有一个词的 CTC 中点落入同一区间、整个原区间在该活动区间 ±一帧内，才允许使用该区间。共享活动区间、跨区间、无锚点、相邻词冲突或任一端变化超过 12000 样本（750ms）时保留原 CTC 并记录原因。
- 每词保留完整文字/码点、原时间及决定。活动区间不是校准过的语音/词正确率；声音、音乐或噪声都可能产生活动，仍须 review。
- 控制器先验证原字符/原词与请求一致，再基于已固定摘要的同一 PCM 独立重算活动结果，拒绝篡改时间、文字、状态或活动摘要；不信任 worker 自报边界。

## 真实核验

1. 原六词与原七词各执行真实模型，分别保留原始和新模式最大误差，不覆盖历史失败。任何一词超门槛即该样本失败。
2. 在取得候选前另生成新声音/新词/非固定间隔的第三组输入，冻结原始词块、来源与摘要；它仍是合成词块，不冒充自然人工精标。
3. 独立检查静音、噪声/DC、低幅度、共享连续活动、短脉冲、错稿及冲突；没有可靠分界时应保留原值及原因。合成解析输入用于算法/契约检查，不计真实模型前向。
4. 产品接入须验证 dry-run、取消/超时、长窗、SRT、帧/样本/码点时钟、入轨及输出篡改拒绝，并从新离线包/实际统一 Skill 核验。原始 CTC 兼容范围不可缩减。
5. 真实渲染和工程包往返分别核验像素/PCM。公开只使用已有发布依据的源；自然中文、听审及独立人工精标继续单列。

根本限制见 PyTorch 的 [CTC blank 与峰值边界说明](https://docs.pytorch.org/audio/stable/tutorials/ctc_forced_alignment_api_tutorial.html#inconsistent-treatment-of-blank-token)。本轮是音频条件边界估计的新实现，不把原模型字符峰重新描述成精确声学真值；部分样本通过不能关闭完整 G15 或完整产品目标。

第三组在候选运行前固定为 `awb` 声音、`SHARP BRIGHT CAMERA FOLLOWS QUIET PEOPLE THROUGH WINTER` 八个新词，词前间隔依次为 0.27/0.08/0.19/0.31/0.12/0.46/0.23/0.37 秒，末尾 0.29 秒；保持 signed-16 原始词块。另一个版本加 DC 173 与交替 ±5 PCM 的背景，参考位置保持不变。作者裁词规则沿用原夹具绝对值≥32，作为摆放参考；算法仍不读取它。所有输入、参考、执行代码和契约在候选执行前记录摘要。

## v2 修订：保留 v1 失败，不改变精度门槛

v1 四次真实 GPU 前向后，原六词/七词仍为 210.0/140.375ms；新 AWB 干净/背景版为 13.25/8.25ms。原六词的弱起始 RMS 常处于 8–27 PCM，而 v1 的全局强音量参考令低阈值达到 27，漏掉真实弱信号；[失败代码快照及诊断](../validation/evidence/ctc-activity-20261025-r1/v1-failure-analysis.json)保留。原始输入/参考/66.6667ms 门槛不变。

**在 v2 候选运行前固定：** `ctc-guided-activity-v2` 仅将低阈值改为 `max(2,2×noise)`，高阈值和其他规则保持；较强信号仍用于接受整个活动区间，不用全局元音强度截掉区间内部的弱音。该规则取决于当前音频噪声底，不读参考、不按词补时。上文 v1 公式用于历史复现。

新增独立输入为 KAL 声音和 `MOTION SIGNAL EDITING TIMELINE SAVES CLEAN FINAL OUTPUT` 八个新词，词前间隔 0.14/0.34/0.09/0.25/0.41/0.16/0.28/0.12 秒，末尾 0.22 秒；其生成与摘要必须早于 v2 推理，仍只作作者合成词块参考。v2 要重跑旧失败、既有 AWB 干净/背景以及新 KAL，不得仅展示通过组。

## v3 修订：弱起始组件的明确归属

v2 五次真实 GPU 前向中四组通过，原七词仍为 105.375ms：弱起始组件存在，但与强活动之间有超过 40ms 的低能量间隔，因此在强活动接受时被丢弃。[v2 原结果与代码快照](../validation/evidence/ctc-activity-20261025-r1/v2-failure-analysis.json)保留。

**在 v3 候选运行前固定：** 保留所有至少 20ms 的低阈值组件和各自 CTC 中点归属。强组件仍须含高阈值帧；弱组件本身没有高阈值帧、也没有 CTC 中点时，仅可附着到相邻、距离不超过 24 帧（120ms）、且恰有一个词锚点的强组件。两侧均符合时保留并记为歧义；两个含词锚点的强组件永不因短间隔合并。附件只使用实际弱组件外边界，不做固定时间扩张；原 750ms 变化、完整原词覆盖、相邻词冲突及低信噪比拒绝规则保持。组件、归属、附件与原始词时间全部保留并由控制器重算。此修订不增加连续内部词界推断的承诺。

v3 另加候选运行前冻结的 KAL16 输入：`AGENTS KEEP EVERY FRAME AND EACH VOICE EDITABLE`，词前间隔 0.22/0.11/0.29/0.14/0.36/0.18/0.31/0.09 秒，末尾 0.22 秒；仍按既有作者裁词规则，原六词/七词及已冻结 AWB/KAL 全部继续评分。该输入是新受控验证条件，不替代自然人工精标。
