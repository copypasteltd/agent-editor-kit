# 原生任务中断与恢复实测（2026-10-25）

[简体 README](../../README.md) · [繁體 README](../../README.zh-TW.md) · [English README](../../README.en.md) · [恢复使用流程](../product/JOB_RECOVERY.md) · [完整目标](../product/GOAL_GAPS_20261025.md)

**本轮补入并实测了 G33 的一部分：原生子进程生命周期、四轨任务工作目录、发布意图、事务提交后的清理，以及强制结束后的显式恢复。完整 G33、自然分离质量和完整产品目标仍未关闭。** 当前本地为 `v0.1.0-alpha.4-local.5` / CLI `0.1.7`；既有公开 alpha.3 和历史附件未改动。

This batch verifies bounded recovery with the actual installed four-source model. It does not establish power-loss, disk-exhaustion, general long-concurrency, natural listening quality or full CapCut parity. Native Windows only; no Docker, WSL, containers or virtual environments were used.

## 问题与修复

上轮辅助脚本强制结束任务后，`cache/four-stem-separation/hdemucs-fql2zn03/` 留下 PCM/request。该旧目录仍是历史失败证据，**没有被本轮管理器删除或冒充已恢复**。正常取消成功不能证明强制结束后也清理成功。

CLI 0.1.7 新建 `cache/managed-jobs/job-<UUID>/`，持原生文件租约至元数据事务完成；输出发布之前持久化路径、文件身份、大小和摘要。显式恢复先回滚待提交元数据，再判断哪些文件仍属于该任务、未被引用且未被替换。已提交资产保留；活跃、未知、变化、阻塞或旧非管理目录保留。

共享 `run_process` 创建暂停子进程，加入不继承的 Windows Job Object 后恢复运行。关闭最后一个句柄时结束该任务的子孙进程；本轮未使用 `taskkill /T` 帮产品完成测试。该机制不是虚拟化或安全沙箱，其他自定义进程路径和第三方服务不自动纳入。

## 四个实际模型任务强制中断

通过固定安装版、既有原生 Torch/TorchAudio 和真实 HDemucs checkpoint 执行。仅结束已知 CLI owner，观察实际 worker；没有按进程名批量停止任务。阶段 2–4 先完成真实模型推理，测试 wrapper 仅在实际发布或提交位置暂停以确定故障时点，**不是未经注入的普通运行**；没有替换模型、DSP、输出或恢复实现。

| 编号 | 强制结束位置 | 结束前状态 | 实际恢复结果 |
|---|---|---|---|
| J06 | worker-loading | 实际 worker 已启动，0 个派生输出；未注入暂停；仅证明启动/完整性阶段 | 只结束 CLI 后真实 worker 的原生句柄确认退出；工作目录清理，元数据与原素材保留 |
| J07 | first-publication | 两次 GPU 模型前向后，1 个 float WAV 已按持久化意图发布，元数据未改 | dry-run 不修改；显式恢复移除该未引用输出与工作目录，源文件保留 |
| J08 | prepared-metadata | 两次 GPU 前向后，4 WAV 和资产/音轨写入，事务日志仍待提交 | 先恢复原元数据，再回收 4 个未引用输出；validate 通过 |
| J09 | committed-metadata | 两次 GPU 前向后，4 WAV/音轨已提交，尚未清理工作目录 | 保留 4 个已引用 WAV、四轨工程及提交后元数据；只清理工作目录，validate 通过 |

四个阶段均检查 dry-run 不改元数据、未登记用户源文件不变、恢复后重复执行为 0 个新增清理。共 **4 个实际强制结束 CLI＋17 次正常 CLI 调用＋6 次真实 GPU 模型前向**；这些不同计数不能相加。记录中的 `stop_and_recovery_seconds` 包含检查/恢复/验证命令时间，不能当作取消确认延迟。

## 失败记录与仍未验收

- 首次开发控制台执行 16 项，辅助测试尝试读取活跃 `owner.lock` 的锁定字节，产生 1 个 PermissionError；当时没有冻结原始日志，不能充作最终通过证据。[保留说明](evidence/job-recovery-20261025-r1/initial-notes.json)。修正测试快照只排除租约字节、保留大小和其他用户文件比较，并补充缺失/损坏项目检查后，最终 17 项分别在开发/安装版通过。
- 首次安装版四轨回归命令的文件匹配写错，发现 **0 项、exit 5**，不是产品推理失败也不是通过。[原样保留](evidence/job-recovery-20261025-r1/installed-four-stem-regression-r1/verification.json)；修正为实际 `test_stem_separation.py` 后在新 r2 证据目录运行 15 项通过，未覆盖旧记录。
- 旧非管理目录的遗留缓存仍保留。其他模型缓存、自定义进程路径、模型中间张量续算、恶意并发改写、断电、磁盘不足、设备丢失、长片/4K、并发公平性和另一台干净物理主机仍未完整验收。
- G15 精确对齐、G16 极短窗音高、G20/G22 自然视频与 G26 否定/库外拒识的原失败继续保留。不能用本轮恢复通过关闭它们。

执行生成器保存在各 evidence 子目录的 `executed-generator.py`。原生复现脚本为 `scripts/run_job_recovery_checks_20261025.py`、`verify_job_recovery_20261025.py` 和 `audit_job_recovery_installation_20261025.py`；选择新的本地输出/证据目录，保留已有实验状态，不重置失败现场。
