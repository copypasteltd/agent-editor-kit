# OpenCL 原生投影实现契约

本批次将 [候选接口](OpenCL投影候选接口_20261026.md) 落为可测试代码。原 G01–G38 关闭条件保持；单项 GPU 接入不代表剪映等价或全特效 GPU 化。最终安装版本、真实验收与失败证据另记本批次验证报告，不能以此设计文档代替实测。

动态裁切、仿射和原生子序列投影共享显式 `projection_acceleration` 策略。默认 `off` 保留原 CPU 算法；`prefer` 允许在执行前因设备、语义或栅格配额拒绝时使用 CPU 并记录原因；`require` 拒绝上述不支持条件和没有适用投影的工程。运行中 GPU 错误不得自动改成 CPU 成功，也不得冒充编码器失败反复重试。独立线性光浮点管线尚未接入，按同一策略处理。

只使用现有 Windows 原生 OpenCL ICD 与现有 FFmpeg，不安装驱动，不调度 Docker/WSL/虚拟环境、后台服务或其他机器。每次渲染记录实际平台/设备索引、名称、驱动、图像尺寸限制和 IEEE binary64 能力。`program_opencl` 按 [FFmpeg n8.1 实现](https://github.com/FFmpeg/FFmpeg/blob/n8.1/libavfilter/vf_program_opencl.c) 的逐平面输入签名工作；不用其递增索引代替作者时间。

系数图由原 AVExpr 在分流源帧的相同 PTS 上求值。binary64 拆为 20/20/余数三段整数及一个指数，四行 Float32 纹理运输；负零、非有限值有显式标记。正式渲染前以包括最大有限数、最小次正规数和负零的原生 GPU 回读比对全部 64 位；失败不能被容差掩盖。shader 不重写 Bezier、hold、嵌套反向时钟或三角函数。动态裁切的 W/H 来自实际源纹理，不能取小系数图尺寸或仅信任探测元数据。

像素核保留 CPU 半像素坐标、裁切、预乘/反预乘、双线性算术顺序。禁止 fast-math 和 FMA 收缩。面积前缀先逐行从左至右求和，再逐列从上至下求和；每个 binary64 和存到三个 Float32 分量，避免先舍为 Float32。面积 footprint 仍是既有源轴矩形，未变为旋转多边形积分。CPU 基线、独立单元交叠和前向标记几何分别验收。

`max_working_bytes` 是投影工作栅格的保守准入估算：累计源帧槽、目标槽、系数纹理、面积两阶段前缀纹理。不是进程总 RAM/总 VRAM 保证，驱动池和其他特效仍占内存。实际纹理尺寸超过设备限制时执行前拒绝；不改变其他 GPU 作业。程序文件按渲染独立写入、记录 SHA-256，并在执行/发布前重新核验；拒绝覆盖旧诊断。

CLI 提供 `--projection-acceleration off|prefer|require`、`--projection-device platform.device` 和 `--projection-memory-mib`。项目、队列、恢复、质量检查和实际 render 必须传递相同策略；dry-run 仅生成计划，不创建 GPU 上下文或诊断文件。渲染保留完整已完成的 FFmpeg 输出、退出码、实际选择和输入指纹。超时/取消由既有原生执行器处理，记录失败且不发布临时成片。

验收须覆盖 gbrap8 与 gbrapf32、全部 fit 模式、奇数/跨画幅、透明隐藏色、半像素、全部关键帧通道、重复/倒退 PTS、嵌套反向、线程独立性、面积双精度前缀与直接交叠、实际 CLI/队列和安装版 Skill。基准保留相同编码器、输入、CPU 资源限制和完整解码/PCM 对照；短片或小画布成绩不能外推为 4K 实时播放、所有 GPU 或全部特效性能。
