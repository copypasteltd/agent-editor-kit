# 非语义原生工作进程：依赖遮蔽复现与修复门禁

## 已复现的行为

CLI56已修复语义工作进程的应用包／原生模型依赖隔离，但不能据此推断其他工作进程已修复。对以下六个实际入口分别复制源码版和已安装版执行隔离子进程，12个观察均发现应用site中的同名依赖优先于模型运行时。

| 编号 | 实际工作进程 | 所属功能 | 源码／安装观察 |
| --- | --- | --- | --- |
| N01 | `enhancement_worker.py` | 本地对白降噪 | 两者均加载控制器依赖标记 |
| N02 | `interpolation_worker.py` | 神经补帧／慢动作 | 两者均加载控制器依赖标记 |
| N03 | `lama_worker.py` | 图像／逐帧修复 | 两者均加载控制器依赖标记 |
| N04 | `lipsync_worker.py` | 本地口型 | 两者均加载控制器依赖标记 |
| N05 | `sam2_worker.py` | 点／框分割 | 两者均加载控制器依赖标记 |
| N06 | `vace_worker.py` | 联合窗口修复／扩画／生成 | 两者均加载控制器依赖标记 |

[实际12项观察](../validation/evidence/native-worker-bootstrap-20261029-r1/r1/verification.json)保留每个原始worker摘要、子进程stdout和stderr。执行入口为[复现驱动](../validation/audit_native_worker_bootstrap.py)。281个应用模块在复现前后与安装版保持字节一致。

测试建立两个不同目录：应用目录和模型依赖目录各有不同的NumPy标记，模型目录同时有不得导入的同名应用包。复制**实际worker**运行，在其首次应用契约导入处输出模块来源并退出，不加载模型、不执行神经推理、不访问网络。12个子进程正常退出，但来源断言失败；结果是 `reproduced-failures`，不能写成12项功能测试通过。

这证明安装目录可能遮蔽注册运行时依赖的机制；不证明六个模型在所有已登记环境上都不能推理，也不撤销其历史真实GPU案例。标记模块用于明确区分搜索路径，不是对真实NumPy／模型的替代质量测试。

## 下一版修复要求

1. 在引入自身应用包时临时置顶所属目录，并在 `finally` 恢复模型Python原生搜索顺序。
2. 核对实际应用包文件属于当前worker目录；不允许已加载或先出现的外部同名应用包接管。
3. 应用子模块通过已固定的包路径加载，NumPy／Pillow／Torch等保留原生模型Python来源。继续保留适配器版本、模块路径、权重和实现摘要核验。
4. 同时检查其他采用相同加载模式的ASR、CTC、分离、OCR、跟踪、抠像和常驻生成入口。静态出现相同代码不等于已经通过动态复现，需补各自实际入口的隔离回归。
5. 保留CLI56的原始失败观察；新版本执行碰撞回归及对应模型／控制／工程兼容测试，再生成独立安装并验证实际原生模型任务。旧适配器不得手工改摘要，按各服务的正式注册／迁移契约重建。

当前CLI56源码与安装的281模块、正式Skill及正在执行的注册入口案例保持冻结。本轮只新增独立复现和修复约束，未将上述六个worker标为已修复。该缺口属于G10／G17／G20／G22／G23／G24／G34的跨运行时交付部分；38项原关闭条件继续保留。


## 扩展检查：全部15入口及复制件候选修复

随后扩展到15个采用该加载方式的入口，补充RVM抠像、人脸、OCR、YOLO跟踪、Demucs、CTC、常驻VACE、四轨分离和Whisper。源码及安装版分别执行15次，共30次均观察到**应用包正确／控制器依赖优先**：[完整失败记录](../validation/evidence/native-worker-bootstrap-20261029-r1/full-r1/verification.json)。已核对30项输出全部是来源标记，不是请求格式失败。

在另外的复制工作区应用拟议的临时导入／归还搜索顺序／包路径核验修复后，同样30次隔离入口观察全部符合原生依赖预期：[候选复制件结果](../validation/evidence/native-worker-bootstrap-20261029-r1/full-proposed-r1/verification.json)。原六入口的12项候选记录也保留在[首轮复制件结果](../validation/evidence/native-worker-bootstrap-20261029-r1/proposed-r1/verification.json)。这些记录明确 `proposed_fix_only=true` 和 `shipped_source_unchanged=true`，不能计为正式源码、安装或模型GPU任务已经修复；完整功能回归／新安装仍须独立执行。
