# CLI63 原生进程清理边界修复

## 问题与证据边界

CLI62 音乐/作曲组 37 项中 1 项在 ffprobe 收尾时报 Owned process enumeration exceeds cleanup budget。原堆栈未记录 Assigned/Count，150 个真实短进程及原用例 10 次观察未重现自然故障。不得断言已证明唯一根因；[CLI62 完整记录](CLI62口型存储竞争修复_2026-10-29.md) 保留。

本轮针对已确认的代码缺陷：旧实现把 Assigned>Count（不完整列表）直接判成超过4096预算，既不重查也不记录实际计数。微软文档区分待返回 ID 数与已返回 ID 数；不完整返回不能直接当成完整列表。[进程列表结构](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_process_id_list) · [QueryInformationJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-queryinformationjobobject)。

## 实现

- 源码版本 CLI0.1.63，现有 native_process_job.py 内修改，无新增产品模块或全局依赖。
- 每次清理最多32次查询，间隔5ms，与终止/等待共享10秒截止时间；不是无限重试。
- 对不完整成功查询，先验证并保留已返回的自有进程句柄，再重查；不能静默当作完整列表。
- 查询失败仅 ERROR_MORE_DATA(234) 可重查，其他权限或 API 错误原样传播。
- Assigned、Count、累计保留句柄均受4096上限约束；非法 Count>Assigned 明确拒绝。
- 持续不完整列表返回 did not stabilize 并记录 assigned/count/attempts/last_error；超上限另报计数，不混淆两类故障。
- 即使活动记账已归零，仍查询列表并等待已知根进程、已保留后代句柄的退出，再关闭 job；仅终止自有 job。
- 错误路径仍明确失败，并关闭自有 KILL_ON_JOB_CLOSE 句柄；不把无法证明的清理写成成功。
