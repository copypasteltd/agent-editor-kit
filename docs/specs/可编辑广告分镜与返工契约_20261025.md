# 可编辑广告分镜、变体与局部返工契约

本批继续推进 G02/G27/G29/G35，不改变 G01–G38 的原关闭条件。

`ad storyboard` 将明确的本地素材选择和已确认文案规划为多个序列；
`ad build` 校验计划摘要、原工程摘要和实际资产内容后原子提交；
`ad revise` 只规划指定变体/镜头的素材、裁切、文案或声音修改，再由 `ad build` 提交。
规划和 dry-run 不改变工程；正常规划只写一个新的项目内报告。

每个变体有独立画布和时长，按项目有理帧率分配完整帧，采用最大余数分配，
每镜头至少一帧，末尾严格落在计划总帧数。实际 tick 边界由帧号独立换算，
不累加浮点时间。素材不足、声音超窗、非法/非有限数、缺失字体、重复 ID、
未知字段、锁定轨道和不匹配的旧计划必须明确失败，不偷偷循环、截台词或换素材。

画面、字幕、逐镜头配音、显式源音和配乐分别可编辑；已有的声音资产可以来自本地
GPU 配音流程。只有明确要求才引入视频源音。不能凭文案生成未提供的商品承诺。
本批的导演决策由 Agent/调用者提供，结构规划器不宣称自动理解素材或独立审美判断。

返工使用稳定镜头/变体 ID，保持未指定镜头、其他变体、原始资产和独立人工编辑。
提交保存原工程快照；失败或中断由现有项目事务恢复。工程包导出/导入后再实际
渲染比较；模型和外部运行时仍按原交付契约处理。

验证覆盖：有理帧率和舍入、多个画幅/时长、素材与声音边界、计划篡改/过期、
文件内容变化、锁定/不完整目标、局部返工的精确影响范围、dry-run、幂等、
真实编码的帧数/画布/PCM、工程包往返及实际统一 Skill。保留所有失败。

演示必须使用实际产品 brief、可公开的输入及来源。自动解码、静帧检查、连续播放、
听审和独立 Agent 自主任务 benchmark 分别记录，不能互相替代。
