# OpenCL 投影候选接口（未集成）

这是后续 G32 的实现约束，不是当前产品能力声明。当前 CLI0.1.19 仍为 CPU 合成和独立硬件编码，原关闭条件保持。本轮没有创建 OpenCL 设备、编译 GPU kernel 或新增 GPU 成片结论。

本机 FFmpeg 8.1 的 `-h filter=program_opencl` 提供 source/kernel/inputs/size。官方 [program_opencl 源码](https://github.com/FFmpeg/FFmpeg/blob/n8.1/libavfilter/vf_program_opencl.c) 显示：每平面分别绑定输出图像、递增索引及对应输入平面，并从第一输入复制帧属性。索引不能直接充当作者 PTS。[OpenCL 帧实现](https://github.com/FFmpeg/FFmpeg/blob/n8.1/libavutil/hwcontext_opencl.c) 对合适的32位通道使用 CL_FLOAT；实际设备/格式能力仍须验证。这里只读 help/源码，没有把选项存在视作可工作的后端。

候选实现由以下数据流替换单个 geq warp，保留前后原有的浮点预乘/反预乘及画布语义：源帧 split，一路保留原图，一路缩成很小的系数图；系数仍由原生 AVExpr 在同一 PTS 计算，再将两路上传到 program_opencl。GPU读取真实源尺寸和系数，不在shader中重写Bezier/hold/嵌套时钟。序列画布/目标尺寸用已知原生尺寸；动态裁切中的 W/H 应由源纹理尺寸恢复，不能误用小系数图的尺寸。

为保持标量精度，可研究将每个binary64系数拆成三个可精确表示的float32分量，通过只读系数纹理还原；零、负数、很小值、边界和float32次正规数必须独立测试。此为待验证推断，不能提前宣称无损。GPU双精度、禁用不受控FMA、浮点纹理上传/下载和Alpha格式必须真实预检。

像素核保持原半像素、clip、双线性算术；面积核需独立比较前缀积分与逐单元交叠，检查求和次序误差，不能以较低精度替代既有验收。重复/倒退PTS、framesync、原生子画布、跨画幅、透明隐藏色和所有变换同时动画均保留。预乘色彩后仅处理当前平面，系数图各平面携带相同参数，以符合逐平面kernel接口。

后端选择须显式记录实际设备与使用/拒绝原因；设备、格式、语义或配额不支持时在执行前按既有策略拒绝或选择 CPU，运行中错误不得冒充成功。内存预算计入上传帧、系数图、输出及kernel临时区；不修改其他GPU任务、不启动任何虚拟化或后台服务。先实现可复现原生实验，再加入正式运行包、Skill和用户文档。
