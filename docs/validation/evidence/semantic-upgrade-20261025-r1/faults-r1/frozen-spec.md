# 语义工程运行时升级契约

目标是解决已有工程绑定旧安装绝对路径、升级后无法执行的问题，保留 G31/G34 的其他完整关闭条件。
新增 `project upgrade-semantic`，使用原适配器 ID、显式新适配器 ID 和派生 ID 前缀。

- 仅当原登记中的全部语义实现模块与当前模块逐文件 SHA/长度相同，且模型、原生 Python、运行依赖和许可证据当前字节均符合原登记时，允许复用已有向量。任何实现、模型或运行库内容变化均拒绝复用，需要重新登记/推理。
- 旧安装目录可以已移动或不可访问；原适配器摘要和有效 Rights Ledger 必须相互绑定。升级不能通过改写原记录、放宽 `verify_adapter`、忽略实现模块或隐藏错误实现。
- 随应用安装的 NumPy/Pillow 等原生依赖按旧 `site/` 内相对位置映射到当前 `site/`，逐文件 SHA/长度相同后才派生新的运行文件清单和模块路径；模型、外部 Python/Torch、许可证据路径不隐式移动。缺失或改变的应用内依赖拒绝升级。真实 worker 的版本/路径校验继续完整执行。
- 新适配器、索引和校准使用新 ID/新目录。原适配器、索引、预览、向量、数据集、校准、权利记录、编辑序列与输入媒体保持不变。
- 新索引保留向量/预览字节、源采样时间/顺序与原推理观察；只派生新身份、路径和相应指纹。新校准保留原 cutoff、fit、observations、dataset、实际设备与查询协议，不重新拟合或调阈值。
- `--dry-run` 完整检查但不写工程、资产或计划。实际提交遵循项目锁、事务、快照、幂等与原生受管目录发布/恢复；失败不得留下被工程引用的半成品。超时/取消沿用可中断字节校验。
- 拒绝重复目标、损坏源/向量/预览/数据集/校准、孤立校准和不足磁盘。输出映射说明原/新 ID、实际复制字节与零新模型前向。

核验使用独立契约测试和真实安装版分开记录。真实案例须先复现旧工程升级拒绝，再执行新命令并在 CPU/CUDA/注册 Skill 上实际查询。冻结的原 80 条查询排序、分数和拒识逐项比较；已知误接受/误拒必须保留。另验证工程包导入、新旧记录/字节保留、取消及事务故障。

这是逐字节相同实现的显式迁移，不承诺不同实现的数值兼容、自然语义改善、模型搬家、跨机器运行依赖或完整剪映等价。保持全部原目标继续推进。
